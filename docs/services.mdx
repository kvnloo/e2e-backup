title: Services
description: Start the dependencies of your app, such as an email API, before the app, and reach them from tests.
---

A service is a dependency of the app under test, such as an email API, an
OAuth provider, or a database. `e2e run` starts each service before the app
commands, shares one instance with every worker, and stops it at the end of
the run.

## Define a service

Write the service as an async generator in `defineService`. Code before the
`yield` starts it, the yielded object is what the config and the tests get,
and code after the `yield` stops it:

```ts title="services/email.ts" expandable
import { once } from 'node:events';
import { createServer } from 'node:http';
import { text } from 'node:stream/consumers';
import { defineService } from 'e2e';

type Email = {
  to: string;
  subject: string;
};

export const email = defineService({
  async *start({ signal }) {
    let emails: Email[] = [];

    const server = createServer(async (request, response) => {
      emails.push(JSON.parse(await text(request)));
      response.end();
    });

    server.listen({ port: 4010, host: '127.0.0.1', signal });

    await once(server, 'listening', { signal });

    yield {
      url: 'http://127.0.0.1:4010',
      sent: () => emails,
      clear: () => {
        emails = [];
      },
    };

    server.close();

    await once(server, 'close');
  },
});
```

Pass `signal` to what the service starts. It aborts when e2e stops waiting
for the service:

- While it starts, when you cancel the run (Ctrl+C) or it hasn't yielded
  within 60 seconds.
- While it stops, when the code after the `yield` hasn't finished within 10
  seconds.

A normal stop doesn't abort it.

## Pass the service to the app

Add the service to `services` in the config, and give the app its address
from an `env` function:

```ts title="e2e.config.ts"
import { defineConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { email } from './services/email.ts';

export default defineConfig({
  projectId: 'dev.example.signup',
  workers: 1,
  services: { email },
  targets: [
    {
      name: 'web',
      engine: web(),
      app: {
        url: 'http://127.0.0.1:0',
        command: {
          executable: 'node',
          args: ['app/server.mjs'],
          env: async ({ services }) => ({
            PORT: '{port}',
            EMAIL_API_URL: services.email.url,
          }),
        },
      },
    },
  ],
});
```

The key in `services` is the service's name. Services start in key order,
before any app command, and stop in reverse order after the app commands.

The `env` function is called one time, after the services start and before
the command is spawned. `{port}` expands in the values it returns. Use
`defineConfig` instead of `satisfies E2EConfig` here: it types `services`
in `env` from the config's `services`.

## Use the service in tests

Pass the config's type to `test.extend` to type the `services` fixture:

```ts title="tests/fixtures.ts"
import { test as base } from 'e2e';
import type config from '../e2e.config.ts';

export const test = base.extend<{}, {}, typeof config>({});
```

Tests, hooks, and fixtures of both scopes can read `services`:

```ts title="tests/signup.e2e.ts"
import { expect } from 'e2e';
import { test } from './fixtures.ts';

test.beforeEach(async ({ services }) => {
  await services.email.clear();
});

test('signing up sends one welcome email', async ({ app, screen, services }) => {
  await app.open('/');
  await screen.getByRole('textbox', { name: 'Email' }).fill('ada@example.com');
  await screen.getByRole('button', { name: 'Sign up' }).click();
  await expect(screen.getByRole('heading', { name: 'Check your inbox' })).toBeVisible();

  expect(await services.email.sent()).toEqual([{ to: 'ada@example.com', subject: 'Welcome' }]);
});
```

Each worker gets a copy of the yielded data. A function becomes an async
function in the test: calling it sends a request to the runner process,
which calls the real function and sends back a copy of the result. So
`services.email.clear()` returns a promise, and it clears the one inbox
every worker shares.

Nothing resets a service between tests. Clear what a test reads in
`beforeEach`, as above.

## What a service can yield

The yielded value is a plain object of any shape. e2e reads it one time,
when the service yields, and checks it then:

- Plain objects and arrays can nest at any depth, and a function can sit at
  any depth too.
- Data, function arguments, and results must survive
  [`structuredClone`](https://developer.mozilla.org/en-US/docs/Web/API/Window/structuredClone).
  Strings, numbers, dates, maps, and plain objects do. A symbol doesn't.
- A class instance loses its class when it's copied, so it's refused. Wrap
  the data and functions tests need in a plain object.
- A function is called with no `this`. Wrap a method that reads `this` in an
  arrow function, such as `reset: () => emulator.reset()`.

## Use emulate as a service

[emulate](https://emulate.dev) runs local emulators of APIs such as GitHub,
Resend, and Stripe. Start one with `createEmulator` and yield what tests
need:

```ts title="services/resend.ts"
import { createEmulator } from 'emulate';
import { defineService } from 'e2e';

export const resend = defineService({
  async *start() {
    const emulator = await createEmulator({ service: 'resend', port: 4008 });

    yield {
      url: emulator.url,
      reset: () => emulator.reset(),
    };

    await emulator.close();
  },
});
```

Yield the address and `reset` instead of the emulator. Otherwise a test
could call `close()` and stop the emulator for every worker.

The Resend Node.js SDK reads its API address from `RESEND_BASE_URL`, so the
app needs no change to send through the emulator.

The test reads the sent emails from the emulator's Resend API:

```ts title="tests/signup.e2e.ts"
import { expect } from 'e2e';
import { test } from './fixtures.ts';

test.beforeEach(async ({ services }) => {
  await services.resend.reset();
});

test('signing up sends a welcome email through Resend', async ({ app, screen, services }) => {
  await app.open('/');
  await screen.getByRole('textbox', { name: 'Email' }).fill('ada@example.com');
  await screen.getByRole('button', { name: 'Sign up' }).click();
  await expect(screen.getByRole('heading', { name: 'Check your inbox' })).toBeVisible();

  const response = await fetch(`${services.resend.url}/emails`);
  const { data } = await response.json();

  expect(data).toEqual([expect.objectContaining({ to: ['ada@example.com'], subject: 'Welcome' })]);
});
```

## When a service fails

| Code | When |
| --- | --- |
| [`SERVICE_START_FAILED`](/reference/errors#runner-codes) | `start` throws, finishes without yielding, or doesn't yield within 60 seconds. The services that already started are stopped, and the run fails. |
| [`INVALID_SERVICE_VALUE`](/reference/errors#runner-codes) | The yielded value isn't a plain object, holds a class instance, or doesn't survive `structuredClone`. |
| [`SERVICE_STOP_FAILED`](/reference/errors#runner-codes) | The code after the `yield` throws, yields again, or doesn't finish within 10 seconds. The run fails with a cleanup error. |

A service function that throws fails the test that called it, like any error
in the test. The error is a copy, and its message names the service and the
function: `services.email.clear() failed: ...`.

Only `e2e run` starts services. `e2e list` starts none, and neither do
`e2e mcp` and `openHost`, which otherwise work as before. There, a test or an
`env` function that reads a service fails with an error that names the
service.
